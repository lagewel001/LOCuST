**Common Query Patterns:**
- **Totals rule:**
  - If the question asks for a total, prefer a measure or dimension code the metadata marks as a total (`(total)` annotation, a MeasureGroup marked `(group of total measures)`, or a label such as one starting with Total) rather than summing over categories yourself.
- **Aggregation coherence** (for every aggregation or comparison across codes or measures: `SUM`, `AVG`, argmin/argmax and proportions):

  - Combining measures from different MeasureGroups is allowed (they are separate families, e.g. pigs + chickens), but NEVER combine a `(total)` measure with other measures of its own MeasureGroup, and never a table-wide total measure (marked `(total)` outside any group, or under a `(group of total measures)` heading) with any other measure: a total already contains what you would add to it.
- **Time and geo levels (`(levels: ...)`):**
  - Geo codes start with a fixed prefix per level: `NL` (Country), `LD` (Region/Landsdeel), `PV` (Province), `GM` (Municipality), `WK` (District/wijk), `BU` (Neighbourhood/buurt); other area classifications have their own prefixes (e.g. `CR` COROP area, `AM` labour market region, `GG` health service region, `LB` agricultural area). District and neighbourhood codes embed the four municipality digits: districts of municipality `GM0363` match `WK0363%`.
  - Period codes follow `<year><infix><2 digits>`: `2023JJ00` (year), `2023KW01` (quarter), `2023MM01` (month), `2023HJ01` (half year).
  - NEVER select a whole level by enumerating codes; use a pattern filter in `WHERE`:
    geo: `Regions LIKE 'WK%'` (all districts), `Regions LIKE 'WK0363%'` (all districts within municipality GM0363);
    time: `regexp_matches(Periods, '^\d{4}KW\d{2}$')` (all quarters), `Periods LIKE '2023KW%'` (the quarters of 2023).
  - Never mix levels in one aggregation or comparison (e.g. municipalities together with provinces, or a year with its quarters): a coarser level already contains the finer ones and double-counts.
  - Argmin/argmax over a level ("which district has the highest ..."): filter the level with LIKE in the `WHERE` of the window-function CTE.
  - Individually listed time/geo codes with a `(relevance: ...)` score are the regions/periods recognized in the question. Use them for filters on named areas/periods and as scopes in pattern filters (e.g. all districts within the recognized municipality `GM0363`: `Regions LIKE 'WK0363%'`).
- **Aggregating over a dimension (`SUM`/`AVG` across several codes of one dimension):**
  - The dimension you aggregate over must only appear in the `WHERE` clause, NEVER in the `SELECT` or the `GROUP BY`: grouping by it puts every code in its own group and returns the individual values instead of the aggregate.
  - Only the dimensions you want to keep apart belong in the `SELECT` and `GROUP BY`. Example: `SELECT Periods, SUM("MeasureA") AS "SUM" ... WHERE Regions IN ('PV20', 'PV21') AND Periods = '2022JJ00' GROUP BY Periods` totals both provinces.
- **Composite measure aggregation (combine multiple measures into one total/avg):**
  - Allowed only if the measures have the same unit AND the same multiplier (compare both parts of the unit annotation).
  - Add the measure columns directly in the aggregation function. Example: `SELECT Periods, SUM("MeasureA" + "MeasureB") AS "SUM" ...`
  - For an average over several measures, divide by the number of measures, so the mean of the measures is taken instead of the mean of their sums: `SELECT Periods, AVG(("MeasureA" + "MeasureB") / 2) AS "AVG" ...`
- **Proportion / ratio:**
  - This is a special query-type that requires an `UNPIVOT`.
  - Use conditional aggregation (`SUM(CASE WHEN ...)`) to compute the percentage (see example 2). A comparison filter on the values goes in the `WHERE` as `Value <op> <number>`.
- **Argmin/argmax ("which X has lowest/highest Y"):**
  - Return the requested dimension value (X) and the min/max value using a window function like `RANK()` in a CTE, ranked separately (`PARTITION BY`) for every combination of the dimensions you keep in the output.
  - Example to find the Period with the minimum value for `<measure>`:
    ```
    WITH RankedRows AS (
        SELECT
            RANK() OVER (PARTITION BY <kept dimensions> ORDER BY "<measure>" ASC) AS rnk,
            <kept dimensions>,
            Periods AS "MIN[Periods]",
            "<measure>"
        FROM "data/en/odata3/<table-id>.parquet"
        WHERE <filters>
    )
    SELECT *
    FROM RankedRows
    WHERE rnk = 1;
    ```
  - If comparing across **measures**, `UNPIVOT` first so you can return the name of the winning measure.
    For example `UNPIVOT(Value FOR Measure IN ('MeasureA', 'MeasureB'))`
- **Combining multiple tables:**
  - Prefer a single table if it contains all needed measures/dimensions.
  - Different measures from different tables, side by side per code of a shared dimension (e.g. per period): `FULL JOIN` the filtered tables on that dimension, plus on shared dimensions that both sides filter on the same codes (never on dimensions filtered on different codes). Subqueries should be simple `SELECT * FROM ... WHERE ...` statements.
    ```
    SELECT COALESCE(TableA.Periods, TableB.Periods) AS Periods, TableA."MeasureA", TableB."MeasureB"
    FROM (SELECT * FROM "data/en/odata3/table1.parquet" WHERE <filters1>) AS TableA
    FULL JOIN (SELECT * FROM "data/en/odata3/table2.parquet" WHERE <filters2>) AS TableB
    ON TableA.Periods = TableB.Periods;
    ```
  - The same measure from two tables (e.g. one measure for areas or categories that are in different tables): stack the rows with `UNION ALL BY NAME`.
    ```
    (SELECT Periods, Regions, "MeasureA" FROM "data/en/odata3/table1.parquet" WHERE <filters1>)
    UNION ALL BY NAME
    (SELECT Periods, Regions, "MeasureA" FROM "data/en/odata3/table2.parquet" WHERE <filters2>);
    ```
  - To aggregate over those stacked values, wrap them: `SELECT 'MeasureA' AS Measure, SUM("MeasureA") AS SUM FROM ((...) UNION ALL BY NAME (...))` (likewise `AVG`, `MIN`, `MAX`).
